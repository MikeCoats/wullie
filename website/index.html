Wullie, yer local groundskeeper

wullie is an opinionated tool for managing dependency requirements in Rust, Python, and JavaScript projects.

Wullie finds out-of-date dependencies in Rust, Python and JavaScript projects, and prints a patch that pins each one to its latest release.

It never changes your files itself. You read the patch, and apply it when you're happy with it.

Why pin exact versions?

Ranges like ^18.2.0, ~=0.24 and >=0.100 are handy while you're developing, but they leave a gap in live, deployed projects. In theory, Cargo, pip and npm install the newest release a range allows, picking up security fixes along the way. In practice, those fixes often don't reach production in good time.

Lock files close part of that gap, but they hide the versions you're really running behind separate files and commands, so it's easy to install an old, insecure one by accident.

Wullie takes a different approach. Every requirement names the exact version you run, and updating is a deliberate step that you take, review and commit.

What it does

Run wullie in your project, and it searches every folder for manifests, looks up each dependency's latest release, and prints the changes as a unified diff: 

--- a/Cargo.toml
+++ b/Cargo.toml
@@ -4,5 +4,5 @@
 edition = "2024"
 
 [dependencies]
-serde = "1.0"
-tokio = { version = "1", features = ["full"] }
+serde = "=1.0.229"
+tokio = { version = "=1.54.1", features = ["full"] }
--- a/api/pyproject.toml
+++ b/api/pyproject.toml
@@ -2,6 +2,6 @@
 name = "api"
 version = "0.1.0"
 dependencies = [
-    "fastapi>=0.100",
-    "httpx~=0.24",
+    "fastapi==0.165.0",
+    "httpx==0.29.0",
 ]
--- a/web/package.json
+++ b/web/package.json
@@ -1,7 +1,7 @@
 {
   "name": "web",
   "dependencies": {
-    "react": "^18.2.0",
-    "vite": "~5.0.0"
+    "react": "19.3.1",
+    "vite": "8.4.0"
   }
 }

When you're happy with the changes, apply them with wullie | git apply, or with patch. Then regenerate and commit your lock files, Cargo.lock, uv.lock, package-lock.json or the equivalent, as Wullie only changes the manifests.

Supported ecosystems

Ecosystem Manifest Registry
Rust Cargo.toml crates.io
Python pyproject.toml PyPI
JavaScript package.json npm

Dependencies on private registries, local paths, git repositories and workspaces are left alone. See what gets checked for the details.

Support for GitHub Actions workflows and Docker Compose files is being looked into.

Install

With cargo-binstall:

cargo binstall wullie

There are also Debian packages, and prebuilt binaries for Linux, macOS and Windows. See Installing Wullie for every option.
